# @ganz404/js-auth v0.1.1

**Release status:** patch release  
**Previous version:** `0.1.0`

## Changes

- Restrict automatic bearer-token attachment, refresh, and retry to requests
  whose origin matches the configured `apiBaseUrl`.
- Requests to other origins are still sent by `auth.http.fetch`, but the SDK
  does not add its bearer token or refresh/retry them after HTTP `401`.
- Add a regression test covering cross-origin requests with an active session.

This update does not change the public API or the Auth Service endpoint
contract.

## Auth Service compatibility audit

The SDK flow matches the inspected Auth Service contract:

- Google login starts at `GET /auth/google?response=frontend`.
- The service validates its OAuth state cookie and Google OIDC nonce, then
  returns access and refresh tokens in the frontend callback URL fragment.
- `handleCallback()` removes that fragment before parsing/storing the tokens
  and only accepts it after a login started in the same tab.
- Refresh uses `POST /api/v1/auth/refresh` with JSON `refresh_token`; the SDK
  handles the response envelope and rotated token pair.
- Logout uses protected `POST /api/v1/auth/logout`; local tokens are cleared
  even when the network request fails.

The JS SDK does not implement JWT verification or Authorization Code + PKCE.
Those are not currently provided as a public-client flow by Auth Service.
Never put an OAuth client secret in browser code.

The broader Auth Service findings and recommendations for version `1.0.0`,
including private-key exposure in Docker image layers, password policy, and
Google redirect configuration, are documented in
[`AUTH_SERVICE_AUDIT_1.0.0.md`](../../auth-service/docs/AUTH_SERVICE_AUDIT_1.0.0.md).
Those service-side issues are not remediated by this SDK release.

## Security behavior

Bearer tokens remain in memory by default. `sessionStorage` remains an
explicit opt-in and is accessible to same-origin JavaScript, so applications
should also prevent XSS. Only send protected API requests to the configured
API origin; make separate unauthenticated `fetch` calls for public third-party
resources.
